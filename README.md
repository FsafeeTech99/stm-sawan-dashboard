# SAWAN — งบพึงรับ รพ.สต. & Statement สปสช.

Streamlit Dashboard สำหรับเครือข่ายบริการสุขภาพ อ.สว่างแดนดิน รพร.สว่างแดนดิน `11450` และ รพ.สต. สังกัด อบจ.สกลนคร เช่น รพ.สต.คำสะอาด `05542` พัฒนาต่อจาก repository เดิม

ใช้งานแบบแต่ละหน่วยอัปโหลดไฟล์เองแล้วกรองของตนเอง ข้อมูล ตัวกรอง ทะเบียนชื่อ และไฟล์ส่งออกแยกตามเซสชัน ไม่มีชุดข้อมูลกลางที่ใช้ร่วมกัน การใช้บัญชีเดียวกันในสองเซสชันไม่ได้แชร์ไฟล์ ปุ่ม **ล้างไฟล์และเริ่มใหม่** ล้างข้อมูลโดยคงการล็อกอินไว้ ส่วนการออกจากระบบล้างทั้งเซสชัน

## เริ่มใช้งาน

ใช้ Python 3.11 หรือ 3.12 แนะนำให้สร้าง virtual environment ภายในโฟลเดอร์โครงการ

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

เปิด `http://localhost:8501` ระบบมีโหมดดูตัวอย่างด้วยข้อมูลสมมติ โหมดนี้ปิดการอัปโหลดข้อมูลจริง

## ตั้งค่าล็อกอิน

ระบบไม่เปิดให้อัปโหลดไฟล์จริงจนกว่าจะตั้งค่าบัญชี ใช้ password hash ไม่เก็บรหัสผ่านตรง ๆ

1. รัน `.venv\Scripts\python scripts/hash_password.py` แล้วพิมพ์รหัสผ่านสองครั้ง รหัสผ่านไม่แสดงบนหน้าจอและไม่อยู่ใน command history
2. คัดลอก `.streamlit/secrets.toml.example` เป็น `.streamlit/secrets.toml`
3. แทน `REPLACE_WITH_GENERATED_HASH` ด้วย hash ที่ได้ เปลี่ยนชื่อบัญชีและชื่อที่แสดงตามต้องการ
4. รีสตาร์ต Streamlit

```toml
[auth.users.finance]
display_name = "เจ้าหน้าที่การเงิน"
password_hash = "pbkdf2_sha256$..."
```

เพิ่มบัญชีด้วย table `[auth.users.<ชื่อบัญชี>]` ได้หลายบัญชี แต่ทุกบัญชีมีสิทธิ์ใช้งานเดียวกัน ไม่มี role หรือขอบเขตแยก รพ.สต. ล็อกเอาต์ล้างข้อมูลเซสชัน เมื่อไม่มีการทำรายการ 30 นาทีจะให้ล็อกอินใหม่ มีการจำกัดการลองรหัสผ่าน 5 ครั้งต่อบัญชีใน 5 นาทีภายใน process เดียว

สำหรับ Streamlit Community Cloud ตั้ง main file เป็น `app.py` แล้วใส่ TOML ในเมนู Secrets ของแอป ไม่ต้อง commit secrets.toml สำหรับการเปิดใช้ผ่านอินเทอร์เน็ตให้ใช้ HTTPS การจำกัดการลองรหัสผ่านนี้เป็นระดับ process ไม่ใช่ระบบจำกัดแบบกระจายหลายเซิร์ฟเวอร์ ไม่มีระบบสมัครสมาชิกหรือกู้รหัสผ่าน

## วิธีใช้

1. อัปโหลดไฟล์พึงรับ รพ.สต. ในกลุ่มแรก เช่น 19–21 ไฟล์ตามแบบ 43 คอลัมน์ และ STM ในกลุ่มที่สอง เช่น 25 ไฟล์ ระบบไม่กำหนดว่าต้องครบจำนวนนี้ รองรับหลายไฟล์/หลายชีตพร้อมกัน ข้อมูลกลุ่มแรกเป็นยอดพึงรับของ รพ.สต. ไม่ใช่ยอดพึงจ่ายของ รพร.
2. ตรวจรายละเอียดการนำเข้า: แถวหัวตาราง คอลัมน์ยอดเงิน จำนวนแถวที่ถูกตัด รหัส/ยอดเงินที่ไม่ถูกต้อง
3. เปิดเมนู **จับคู่คอลัมน์** หากระบบเลือกไม่ตรง โดยเฉพาะรหัสให้เลือก `HSUB` สำหรับ รพ.สต. ถ้าไม่มี HSUB จะเลือก HCODE ของผู้ให้บริการตามไฟล์ตัวอย่าง ส่วน HCODE_PAID เป็นหน่วยที่รับโอน ไม่ใช้แทนรหัส รพ.สต. คอลัมน์ยอดเงินหลักในแบบนี้คือ `ยอดชดเชยทั้งสิ้น`
4. เลือกคอลัมน์งวด หรือพิมพ์งวดให้ทั้งชีต เช่น `2569-09` ให้ตรงกันทั้งสองชุด หากไม่มีงวด/เดือน ระบบใช้ REP เต็มรหัสเป็นกลุ่มเทียบรายงานเดียวกัน โดยไม่ถอดความหมายปี/เดือนจาก REP ระบบจับคู่ข้อความเดียวกันเท่านั้น ไม่แปลงระหว่างปี พ.ศ./ค.ศ. หรือเดือนภาษาไทย และไม่ใช้วันรักษาเป็นงวด
5. ค้นหา `05542`, `5542`, `คำสะอาด` หรือเลือกหน่วยบริการและงวด ตัวกรองใช้ร่วมกันทั้ง 3 แท็บ
6. ดาวน์โหลด Excel ในแต่ละแท็บ ปุ่มส่งออกใช้ผลกรองปัจจุบัน แท็บเปรียบเทียบส่งออกตามสถานะที่เลือกเพิ่มด้วย

### แท็บ 1: รวมไฟล์พึงรับ รพ.สต.

รวมรายการจากทุกไฟล์เข้าตารางเดียวตามหัว 43 คอลัมน์ในไฟล์ตัวอย่าง แสดงยอดสุทธิ ยอดบวก ยอดปรับลด/เรียกคืน PP สุทธิ และสรุปแต่ละ รพ.สต. แยก PP, FS, OP, HC, DRUG, AE, INST, DMIS_DRUG, Palliative care, DMISHD และคอลัมน์ยอดคำนวณ/จ่ายจริงที่เลือก ผู้ใช้เลือกหมวดและแยกงวด/REP ได้

ไม่ตัดจำนวนลบออกจากยอดสุทธิ และไม่บวกยอดหมวดเข้าด้วยกันเพื่อสร้างยอดชดเชยทั้งสิ้น เพราะบางคอลัมน์เป็นยอดย่อยที่ซ้อนกัน ถ้าข้อมูลหมวดไม่ครบจะแสดงว่างแทนศูนย์ ไฟล์งบพึงรับแบบตารางสรุปเดิมที่ไม่มี TRAN_ID/ยอดชดเชยทั้งสิ้นยังรองรับโดยจับคู่คอลัมน์ยอดพึงรับ

### แท็บ 2: STM

ใช้คอลัมน์ตามแบบที่ให้มาเท่านั้นและเรียงตามลำดับเดิม คอลัมน์ที่ไม่มีในไฟล์แสดงว่าง ส่วน HSUB งวด และไฟล์ต้นทางอยู่ในชีตอ้างอิง ไม่เพิ่มในตารางรายละเอียด STM

หัวตารางมีชื่อซ้ำ เช่น `DRUG`, `ยอดชดเชยที่คำนวณได้`, `ยอดชดเชยที่จ่ายจริง` ระบบเก็บครบทั้งสองตำแหน่งและติด `(2)` ให้ตำแหน่งที่สองตามลำดับซ้ายไปขวาในหน้าจอ ส่วนชีตรายละเอียด Excel ใช้หัวซ้ำเดิมตามไฟล์ตัวอย่าง ไม่รวมยอดคอลัมน์ย่อยเข้ากับยอดชดเชยทั้งสิ้น เพราะจะทำให้นับยอดซ้ำ

### แท็บ 3: เปรียบเทียบ

**ผลต่างรอตรวจสอบ = งบพึงรับ − ยอดชดเชย STM** โดยรวมยอดแต่ละชุดก่อนจับคู่ `หน่วยบริการ + งวด` ไม่ join แถวผู้ป่วยเข้าหากัน จึงไม่เกิดการคูณจำนวนแถว

- ค่าบวก: งบพึงรับสูงกว่า STM
- ค่าลบ: STM สูงกว่างบพึงรับ
- งวด/หน่วยบริการที่มีข้อมูลข้างเดียว: ยอดฝั่งที่ไม่มีข้อมูลและผลต่างแสดงว่าง ไม่ถือว่าเป็นศูนย์
- ไม่ระบุงวด: แสดงยอดของแต่ละชุดแต่ไม่คำนวณผลต่างจนกว่าจะกำหนดงวด

ผลต่างนี้เป็นข้อมูลประกอบการตรวจสอบ ไม่ใช่ยอดเงินโอนให้ รพ.สต. จริงหรือยอดค้างจ่ายที่ยืนยันแล้ว

## การอ่าน Excel และคุณภาพข้อมูล

- ใช้ `openpyxl` สำหรับ XLSX และ `xlrd` สำหรับ XLS โดยตรวจ signature ไฟล์จริง รองรับ XLSX ที่เปลี่ยนนามสกุลเป็น .xls
- อ่าน raw sheet แบบ `header=None, dtype=object` แล้วตรวจหัวตารางใน 40 แถวแรกด้วยชื่อคอลัมน์จริง รองรับหัวรายงาน 5–8 แถวและหัวตารางหลายชั้นไม่เกิน 3 แถว
- หากตรวจไม่พบ ให้ระบุเลขแถวหัวตารางเองในเมนูตั้งค่าหัวตารางของไฟล์ การระบุเลขแถวใช้กับทุกชีตในไฟล์นั้นและหัวตารางชั้นเดียว
- ตารางต้องมีรหัสและยอดเงิน/ข้อมูลรายการที่รู้จักอย่างน้อย 3 ชื่อ หากเป็นไฟล์แบบ 2 คอลัมน์หรือชื่อเฉพาะให้ตั้งแถวเองแล้วจับคู่คอลัมน์
- บังคับ HCODE, HSUB, HCODE_PAID เป็น string 5 หลัก ค่าว่าง/รหัสผิดไม่ถูกเปลี่ยนเป็น `00000` และไม่ใช้คอลัมน์รหัสผิดในการรวมยอด
- เงินรวมใช้จำนวนเต็มหน่วยสตางค์ รองรับ comma และจำนวนลบแบบวงเล็บ ยอดเงินว่างหรือผิดไม่ถูกแทนด้วยศูนย์
- ตัดแถวว่าง แถวรวม และหัวตารางที่พิมพ์ซ้ำกลางรายงาน รายการที่รหัส/ยอดเงินผิดยังอยู่ในรายละเอียดและมีตารางปัญหาให้ตรวจ
- ไฟล์ที่เนื้อหาเหมือนกันถูกอ่านครั้งเดียว มีตัวเลือกตัดแถวธุรกิจที่เหมือนกันข้ามไฟล์/ชีต โดยรักษาจำนวนรายการซ้ำในชีตเดิมและรายการที่ TRAN_ID เหมือนแต่ยอดต่างกัน หากแถวเหมือนกันเป็นคนละรายการจริงให้ปิดตัวเลือกนี้
- ค้นหารหัสตรงรหัสหน่วยบริการเป้าหมายเท่านั้น ชื่อค้นหาแบบ literal ไม่ใช้ regex ชื่อค้นได้จากไฟล์หรือทะเบียนหน่วยบริการ เพิ่มทะเบียนได้ทาง sidebar
- ข้อมูลนำเข้าเก็บเฉพาะ session ไม่ cache ข้ามผู้ใช้ Export ใช้ BytesIO ไม่เขียนไฟล์ผู้ป่วยบนเซิร์ฟเวอร์ ป้องกันข้อความนำเข้าไม่ให้กลายเป็นสูตร Excel
- HN/AN/PID ที่ถูก Excel บันทึกเป็นตัวเลขจนเลขศูนย์หาย ไม่สามารถกู้ศูนย์ได้หากไม่ทราบความยาวที่ถูกต้อง กฎเติมศูนย์ 5 หลักใช้เฉพาะรหัสหน่วยบริการ
- ไม่รองรับ HTML ที่ปลอมเป็น .xls, ไฟล์เข้ารหัส, macro และหลายตารางในชีตเดียว หากเป็น HTML จะมีข้อความแจ้งให้แปลงเป็น Excel จริง

## ทดสอบ

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m unittest discover -s tests -v
```

ทดสอบไฟล์ XLS/XLSX จริงที่สร้างขึ้นในหน่วยความจำ หัวรายงาน 5–8 แถว หัวหลายชั้น คอลัมน์ซ้ำ รหัสเลขศูนย์นำหน้า ค้นหา แถวรวม เงินผิดพลาด ตัดข้อมูลซ้ำ เปรียบเทียบงวด และ export รวมถึงการลองนำเข้า 20 + 25 ไฟล์ และ Streamlit AppTest สำหรับล็อกอิน ตัวกรอง และล็อกเอาต์

ยืนยันการอ่านแบบ 43 คอลัมน์และยอดสุทธิกับไฟล์ตัวอย่างรวมไฟล์ที่ผู้ใช้ส่งแล้ว ไม่บรรจุไฟล์จริงหรือข้อมูลผู้ป่วยในโค้ด/ชุดทดสอบ ต้องตรวจยอดอีกครั้งเมื่อได้รับครบ 19–21 ไฟล์และ STM อีกชุด

ตรวจด้วย unit tests และ Streamlit AppTest พร้อมตรวจไฟล์ตัวอย่างจริงผ่านการทำงานของแอป มีการทดสอบผู้ใช้สองเซสชันที่อัปโหลดคนละไฟล์และใช้ตัวกรองคนละค่า การดูภาพหน้าจอในเครื่องยังตรวจไม่ได้เนื่องจากเบราว์เซอร์ที่เชื่อมต่อไม่เข้าถึง localhost ของสภาพแวดล้อมทดสอบ สถานะการเผยแพร่ให้ยึดผลจริงจาก GitHub/Streamlit Cloud
