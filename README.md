# KhamTechReCheck — งบพึงรับ รพ.สต. & Statement สปสช.

Streamlit Dashboard สำหรับเครือข่ายบริการสุขภาพ อ.สว่างแดนดิน รพร.สว่างแดนดิน `11450` และ รพ.สต. สังกัด อบจ.สกลนคร เช่น รพ.สต.คำสะอาด `05542` พัฒนาต่อจาก repository เดิม

ใช้งานแบบแต่ละหน่วยอัปโหลดไฟล์เอง ข้อมูลและตัวกรองแยกตามเซสชัน บัญชีแต่ละหน่วยเห็นและส่งออกเฉพาะรหัสของตนเอง แม้อัปโหลดไฟล์รวมหลายหน่วยเข้ามา ทะเบียนชื่อคงที่ตาม 19 หน่วยในรายการของผู้ใช้ ไม่มีชุดข้อมูลกลางที่ใช้ร่วมกัน ปุ่ม **ล้างไฟล์และเริ่มใหม่** ล้างข้อมูลโดยคงการล็อกอินไว้ ส่วนการออกจากระบบล้างทั้งเซสชัน

## เริ่มใช้งาน

### ไฟล์ดิบ / ไฟล์รวม / จำนวนไฟล์มาก

- ช่องอัปโหลดทั้งสองกลุ่มรับ `.xls` และ `.xlsx` หลายไฟล์ ไม่มีการจำกัดจำนวนไว้ที่ 19–20 หรือ 25 ไฟล์; ขนาดสูงสุดตาม config คือ **100 MB ต่อไฟล์** จำนวนแถวและขนาดรวมยังขึ้นกับ RAM ของเครื่องหรือเว็บ
- เลือกไฟล์ดิบแยกงวด หรือไฟล์ที่รวมรายรายการมาแล้วได้ หากแยกชีต แต่ละชีตสามารถเรียงคอลัมน์ต่างกัน เพราะระบบตรวจหัวตารางแต่ละชีต
- ไฟล์รวมชีตเดียวต้องจัดข้อมูลใต้หัวคอลัมน์ให้ตรงกัน รักษา HSUB/HCODE และ REP รายแถวไว้ ระบบเลือก REP ที่มีข้อมูลก่อนงวด/เดือน เพื่อเก็บ 2–3 งวดในเดือนเดียวกัน
- หัวตารางซ้ำรูปแบบเดิมและแถวรวมจะถูกตัดออก หากพบหัวตารางซ้ำที่เรียงคอลัมน์ต่างกันในชีตเดียว ระบบแจ้งข้อผิดพลาดและไม่รวมชีตนั้น ต้องจัดหัวคอลัมน์ให้ตรงกันหรือแยกชีต หากย้ายค่าเองโดยไม่เหลือหัวบอกไว้ ระบบไม่สามารถตรวจพบความผิดพลาดทุกชนิดได้
- ไฟล์ที่เหลือเฉพาะยอดสรุป ไม่มีรายรายการ/รหัสหน่วย/งวด/หมวดบริการ ไม่สามารถให้รายละเอียดเทียบเท่าไฟล์ดิบได้ ข้อมูลที่หายไปจะไม่ถูกสร้างขึ้นใหม่
- ตั้งค่าหัวตารางและจับคู่คอลัมน์ผ่านตัวเลือกไฟล์/ชีตทีละรายการ ค่าของชีตที่ไม่ได้เปิดแก้ยังอยู่ในเซสชัน ไม่สร้างช่องตั้งค่าหลายพันช่องเมื่ออัปโหลด 200 ไฟล์
- มีจำนวนไฟล์ ขนาดรวม แถบความคืบหน้า และสรุปจำนวนชีต/รายการ/งวดที่ประมวลผล ตรวจชีตที่อ่านไม่ได้ใน ‘ตรวจการนำเข้า’ ก่อนใช้งานยอด
- แนะนำเลือกไฟล์ดิบหรือไฟล์รวมของช่วงข้อมูลนั้นอย่างใดอย่างหนึ่ง การตัดซ้ำตรวจเฉพาะข้อมูลรายการที่ตรงกันทั้งหมดและรักษารายการซ้ำภายในชีตเดิม หากไฟล์รวมแก้ชื่อ/รูปแบบ/คอลัมน์หรือรวมซ้ำมาแล้ว ไม่รับประกันว่าตรวจซ้ำได้ครบ
- ทดสอบด้วย 200 ไฟล์จำลอง (XLS 100 + XLSX 100), 2,000 รายการ, 3 REP ยอดเท่ากับไฟล์รวมเดียว รวมถึงทดสอบหน้าแอป 200 ไฟล์ การเก็บค่ารายชีต และโครงสร้างต่างกันระหว่างชีต นี่เป็นการทดสอบชุดข้อมูลจำลอง ไม่ใช่การรับประกันว่าทุกชุด 200 ไฟล์ขนาดใหญ่จะพอดีกับ RAM ของ Cloud

### ตรวจ HC / HC-DRUG / PP / FS และติดตามบริการ

- แท็บ 01–02 มีการ์ดสรุป 5 หมวดพร้อมจำนวนรายการที่อ่านยอดไม่ได้ ยอดรวมยึดต้นทาง ไม่บวกหมวดเข้าด้วยกัน
- แท็บ 04 และ 05 มีตัวกรองหมวด ชื่อบริการ คำค้น HN/เลขบัตร/ชื่อ และสถานะติดตาม เลือกหลายหมวดแบบ OR แถวยังนับครั้งเดียว
- รักษาคอลัมน์ `บริการ` และ `HC-DRUG` จาก Excel ถ้ามี หากไม่มี HC-DRUG ใช้ DRUG ตำแหน่งแรกตามตัวอย่างผู้ใช้ เปลี่ยนเป็น DRUG ตำแหน่งที่สองหรือไม่จับคู่ได้ใน sidebar
- ตัวเลือกช่องว่าง/ขีดเป็นศูนย์ใช้เฉพาะหมวดที่มีคอลัมน์อยู่จริง ยอดรวมว่าง คอลัมน์ที่ไม่มี และค่าที่อ่านไม่ได้ยังคงเป็นไม่ทราบยอด
- กรอก `บริการที่ตรวจเอง` ติ๊ก `ต้องติดตาม` และกรอก `ยอดตามสมุนไพร (กรอกเอง)` / `ยอดตาม PP (กรอกเอง)` แล้วบันทึก ยอดติดตามเป็นจำนวนเงินที่ผู้ใช้ระบุ ไม่ใช่การนำเรียกเก็บลบชดเชยโดยอัตโนมัติ
- ชื่อบริการจากไฟล์ ชื่อที่ตรวจเอง และชื่อประมาณการจากราคาแยกกัน ยอดต้นทางแก้ไม่ได้ บันทึกอยู่เฉพาะเซสชันและผูกกับเนื้อหา/แถว/ไฟล์ของบัญชีนั้น ควร Export ก่อนออกจากระบบ
- แท็บ 03 เพิ่มผลต่างรายหมวด พึงรับลบ STM เฉพาะหน่วยและงวดเดียวกันที่มีข้อมูลครบ ยังคงใช้คำว่าผลต่างรอตรวจสอบ
- Export ประกอบด้วยสรุปยอด สรุปบริการ รายละเอียด และรายการติดตามตามตัวกรอง ค้นด้วยเลขบัตรได้แต่ไม่ส่งออกเลขบัตรจากชุดสรุปนี้

ใช้ Python 3.11 หรือ 3.12 แนะนำให้สร้าง virtual environment ภายในโฟลเดอร์โครงการ

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

เปิด `http://localhost:8501` ระบบมีโหมดดูตัวอย่างด้วยข้อมูลสมมติ โหมดนี้ปิดการอัปโหลดข้อมูลจริง

## บัญชีหน่วยบริการ

มีบัญชีคงที่ 19 หน่วยตามภาพที่ผู้ใช้กำหนด ไม่รวมบัญชีแม่ข่าย 11450 และไม่รับบัญชี finance เดิม ชื่อผู้ใช้เป็น `Admin` ต่อด้วยรหัส 5 หลัก รหัสผ่านเริ่มต้นเป็นรหัส 5 หลักเดียวกัน เช่น `Admin05542` / `05542` หรือ `Admin13977` / `13977` ต้องคงเลขศูนย์นำหน้าและตัว A ใหญ่

รายชื่ออยู่ใน `dashboard/registry.py` และเก็บรหัสผ่านเป็น PBKDF2 hash ใน `dashboard/account_hashes.json` ระบบเลือกขอบเขตตามบัญชีฝั่งเซิร์ฟเวอร์จาก HSUB ก่อน HCODE ไม่ใช้ HCODE_PAID หรือค่าตัวกรองในหน้าเว็บเป็นสิทธิ์เข้าถึง ตาราง รายละเอียด สรุป PP การเปรียบเทียบ และ Excel ทั้งหมดใช้ข้อมูลหลังจำกัดรหัสแล้ว

รหัสเริ่มต้นตามรหัสหน่วยบริการเดาได้ง่าย ผู้ดูแลสามารถเปลี่ยนรหัสผ่านก่อนใช้กับข้อมูลผู้ป่วยจริง โดยใส่ hash ใหม่ใน Secrets เฉพาะบัญชีที่อยู่ในทะเบียน การเพิ่มชื่อบัญชีอื่นหรือ facility_code ใน Secrets ไม่ขยายขอบเขตหน่วยบริการ

### เปลี่ยนรหัสผ่านของบัญชีที่มีอยู่

1. รัน `.venv\Scripts\python scripts/hash_password.py` แล้วพิมพ์รหัสผ่านสองครั้ง รหัสผ่านไม่แสดงบนหน้าจอและไม่อยู่ใน command history
2. คัดลอก `.streamlit/secrets.toml.example` เป็น `.streamlit/secrets.toml`
3. แทน `REPLACE_WITH_GENERATED_HASH` ด้วย hash ที่ได้ ระบุชื่อบัญชี Admin ตามรหัสในทะเบียน
4. รีสตาร์ต Streamlit

```toml
[auth.users.Admin05542]
password_hash = "pbkdf2_sha256$..."
```

เปลี่ยน hash ด้วย table `[auth.users.Admin<รหัส>]` ได้เฉพาะ 19 บัญชีเดิม ชื่อหน่วยบริการและขอบเขตรหัสยังยึดทะเบียนเดิม ล็อกเอาต์ล้างข้อมูลเซสชัน เมื่อไม่มีการทำรายการ 30 นาทีจะให้ล็อกอินใหม่ มีการจำกัดการลองรหัสผ่าน 5 ครั้งต่อบัญชีใน 5 นาทีภายใน process เดียว

สำหรับ Streamlit Community Cloud ตั้ง main file เป็น `app.py` แล้วใส่ TOML ในเมนู Secrets ของแอป ไม่ต้อง commit secrets.toml สำหรับการเปิดใช้ผ่านอินเทอร์เน็ตให้ใช้ HTTPS การจำกัดการลองรหัสผ่านนี้เป็นระดับ process ไม่ใช่ระบบจำกัดแบบกระจายหลายเซิร์ฟเวอร์ ไม่มีระบบสมัครสมาชิกหรือกู้รหัสผ่าน

## วิธีใช้

1. อัปโหลดไฟล์พึงรับ รพ.สต. ในกลุ่มแรก เช่น 19–21 ไฟล์ตามแบบ 43 คอลัมน์ และ STM ในกลุ่มที่สอง เช่น 25 ไฟล์ ระบบไม่กำหนดว่าต้องครบจำนวนนี้ รองรับหลายไฟล์/หลายชีตพร้อมกัน ข้อมูลกลุ่มแรกเป็นยอดพึงรับของ รพ.สต. ไม่ใช่ยอดพึงจ่ายของ รพร.
2. ตรวจรายละเอียดการนำเข้า: แถวหัวตาราง คอลัมน์ยอดเงิน จำนวนแถวที่ถูกตัด รหัส/ยอดเงินที่ไม่ถูกต้อง
3. เปิดเมนู **จับคู่คอลัมน์** เพื่อเลือกยอดเงิน ระบบล็อกคอลัมน์รหัสให้ใช้ `HSUB` ถ้ามี หรือ HCODE ของผู้ให้บริการเมื่อไม่มี HSUB ส่วน HCODE_PAID เป็นหน่วยที่รับโอน ไม่ใช้แทนรหัส รพ.สต. คอลัมน์ยอดเงินหลักในแบบนี้คือ `ยอดชดเชยทั้งสิ้น`
4. เลือกคอลัมน์งวด หรือพิมพ์งวดให้ทั้งชีต เช่น `2569-09` ให้ตรงกันทั้งสองชุด หากไม่มีงวด/เดือน ระบบใช้ REP เต็มรหัสเป็นกลุ่มเทียบรายงานเดียวกัน โดยไม่ถอดความหมายปี/เดือนจาก REP ระบบจับคู่ข้อความเดียวกันเท่านั้น ไม่แปลงระหว่างปี พ.ศ./ค.ศ. หรือเดือนภาษาไทย และไม่ใช้วันรักษาเป็นงวด
5. ค้นหา `05542`, `5542`, `คำสะอาด` หรือเลือกงวด ตัวกรองใช้ร่วมกันทั้ง 5 แท็บ รหัสหน่วยบริการถูกล็อกตามบัญชี
6. ดาวน์โหลด Excel ในแต่ละแท็บ ปุ่มส่งออกใช้ผลกรองปัจจุบัน แท็บเปรียบเทียบส่งออกตามสถานะที่เลือกเพิ่มด้วย

### แท็บ 1: รวมไฟล์พึงรับ รพ.สต.

รวมรายการจากทุกไฟล์เข้าตารางเดียวตามหัว 43 คอลัมน์ในไฟล์ตัวอย่าง แสดงยอดสุทธิ ยอดบวก ยอดปรับลด/เรียกคืน PP สุทธิ และสรุปแต่ละ รพ.สต. แยก PP, FS, OP, HC, DRUG, AE, INST, DMIS_DRUG, Palliative care, DMISHD และคอลัมน์ยอดคำนวณ/จ่ายจริงที่เลือก ผู้ใช้เลือกหมวดและแยกงวด/REP ได้

ไม่ตัดจำนวนลบออกจากยอดสุทธิ และไม่บวกยอดหมวดเข้าด้วยกันเพื่อสร้างยอดชดเชยทั้งสิ้น เพราะบางคอลัมน์เป็นยอดย่อยที่ซ้อนกัน ถ้าข้อมูลหมวดไม่ครบจะแสดงว่างแทนศูนย์ ไฟล์งบพึงรับแบบตารางสรุปเดิมที่ไม่มี TRAN_ID/ยอดชดเชยทั้งสิ้นยังรองรับโดยจับคู่คอลัมน์ยอดพึงรับ

### แท็บ 2: STM

ใช้คอลัมน์ตามแบบที่ให้มาเท่านั้นและเรียงตามลำดับเดิม คอลัมน์ที่ไม่มีในไฟล์แสดงว่าง ส่วน HSUB งวด และไฟล์ต้นทางอยู่ในชีตอ้างอิง ไม่เพิ่มในตารางรายละเอียด STM

หัวตารางมีชื่อซ้ำ เช่น `DRUG`, `ยอดชดเชยที่คำนวณได้`, `ยอดชดเชยที่จ่ายจริง` ระบบเก็บครบทั้งสองตำแหน่งและติด `(2)` ให้ตำแหน่งที่สองตามลำดับซ้ายไปขวาในหน้าจอ ส่วนชีตรายละเอียด Excel ใช้หัวซ้ำเดิมตามไฟล์ตัวอย่าง ไม่รวมยอดคอลัมน์ย่อยเข้ากับยอดชดเชยทั้งสิ้น เพราะจะทำให้นับยอดซ้ำ

### แท็บ 3: เปรียบเทียบ

**ผลต่างรอตรวจสอบ = งบพึงรับ − ยอดชดเชย STM** โดยรวมยอดแต่ละชุดก่อนจับคู่ `หน่วยบริการ + งวด` ไม่ join แถวผู้ป่วยเข้าหากัน จึงไม่เกิดการคูณจำนวนแถว

- ค่าบวก: งบพึงรับสูงกว่า STM
- ค่าลบ: STM สูงกว่างบพึงรับ
- งวด/หน่วยบริการที่มีข้อมูลข้างเดียว: ยอดฝั่งที่ไม่มีข้อมูลและผลต่างแสดงว่าง ไม่ถือว่าเป็นศูนย์
- ไม่ระบุงวด: แสดงยอดของแต่ละชุดแต่ไม่คำนวณผลต่างจนกว่าจะกำหนดงวด

ผลต่างนี้เป็นข้อมูลประกอบการตรวจสอบ ไม่ใช่ยอดเงินโอนให้ รพ.สต. จริงหรือยอดค้างจ่ายที่ยืนยันแล้ว

### แท็บ 4: รายละเอียดบริการ

เลือกชุดพึงรับหรือ STM แล้วคลิกปุ่ม PP / FS / Drug / HC หรือเลือกหมวด OP, AE, INST, Drug ตำแหน่งที่สองเพิ่มเติม ตารางแจกแจงราคาแต่ละยอด จำนวนแถว ยอดบวก ยอดติดลบ ยอดสุทธิ และชื่อบริการประมาณการ คลิกแถวราคา หรือเลือกยอดจาก dropdown เพื่อดู REP, TRAN_ID, HN, PROJCODE, ยอดหมวดนั้น ยอดชดเชยทั้งสิ้น และไฟล์/ชีต/แถวต้นทาง

- PP 80 บาท → หญิงไทยแก้มแดง / Ferrofolic
- PP 60 บาท → FIT test
- PP 360 บาท → ฝากครรภ์ ANC
- HC → ชื่อหมวดยาสมุนไพรตามที่ผู้ใช้กำหนด ไม่ยืนยันชนิดยาและจำนวนหน่วยยา
- FS 49 บาท หรือราคาอื่นที่ไม่ตรง → ยังจับคู่บริการไม่ได้ ไม่ปัดเป็น 40/60/80
- PP 50, 150 หรือ 20 บาทตรงหลายกิจกรรม → แสดงรายการที่เป็นไปได้ทั้งหมด ไม่เลือกกิจกรรมใดเป็นข้อมูลยืนยัน

อัตราอ้างอิง 21 กิจกรรมมาจากภาพปีงบประมาณ 2570 ที่ผู้ใช้ส่ง เป็นตารางสำหรับเทียบราคา ไม่ใช่อัตราจ่ายปัจจุบันที่ตรวจยืนยันกับ สปสช. และไม่ยืนยันเงื่อนไขอายุ/สิทธิ/จำนวนครั้งจากยอดเงิน ใช้ราคาต่อแถวตรงกัน ไม่หารยอดรวมเพื่อเดาจำนวนบริการ ไม่ใช้ราคาเพียงอย่างเดียวแปลงทุก OP เป็น OP Anywhere

เจ้าหน้าที่เพิ่มหรือแก้ชื่อประมาณการตามหมวด+ราคาได้ใน sidebar กฎอยู่ในเซสชันและใช้กับสองชุดข้อมูลแยกกัน ไม่เปลี่ยนยอดเงินต้นทาง ไม่ขยายรหัสหน่วยบริการ หากมีกฎราคาเดียวกันแต่ชื่อขัดกันจะกลับไปใช้ตารางอ้างอิง สามารถ Export สรุปราคา รายละเอียดที่เลือก กฎที่ใช้ และตารางอ้างอิงเป็น Excel ได้

### แท็บ 5: Walk-in

ตามข้อกำหนดผู้ใช้ คัดจาก PROJCODE ที่ระบุ `WALKIN`, `WALK-IN`, `WALK IN` (ไม่สนตัวพิมพ์) และรหัสที่มี marker นี้กับ suffix เช่น WALKIN01 ไม่รวม NON/NOT/NO WALKIN และไม่ใช้ OP เป็นเกณฑ์แทน หากไม่มี PROJCODE หรือไม่พบ marker แสดงสถานะไม่มีข้อมูล ไม่สมมติว่าเป็น Walk-in

แสดงยอดชดเชยทั้งสิ้นจากไฟล์ และ PP, FS, Drug, HC ของกลุ่ม Walk-in แยกคอลัมน์ พร้อมตารางรายรายการว่าแต่ละแถวมีเงินหมวดใดและอาจตรงบริการอะไร เจาะหมวด/ราคาต่อได้เหมือนแท็บ 4 ไม่มีการรวมพึงรับและ STM เข้าด้วยกัน จำนวนรายการหมายถึงจำนวนแถว ไม่ยืนยันว่าเป็นจำนวนคนหรือจำนวน visit ที่ไม่ซ้ำ

ชื่อผู้รับบริการในหน้ารายละเอียดบริการและ Walk-in ปิดไว้เริ่มต้น เปิดแสดงได้ตามต้องการ ทั้งหน้าจอและ Excel ใช้ตัวเลือกเดียวกัน รายละเอียด 43 คอลัมน์ในแท็บเดิมยังคงรูปแบบตามที่ผู้ใช้ขอ

## การอ่าน Excel และคุณภาพข้อมูล

- ใช้ `openpyxl` สำหรับ XLSX และ `xlrd` สำหรับ XLS โดยตรวจ signature ไฟล์จริง รองรับ XLSX ที่เปลี่ยนนามสกุลเป็น .xls
- อ่าน raw sheet แบบ `header=None, dtype=object` แล้วตรวจหัวตารางใน 40 แถวแรกด้วยชื่อคอลัมน์จริง รองรับหัวรายงาน 5–8 แถวและหัวตารางหลายชั้นไม่เกิน 3 แถว
- หากตรวจไม่พบ ให้ระบุเลขแถวหัวตารางเองในเมนูตั้งค่าหัวตารางของไฟล์ การระบุเลขแถวใช้กับทุกชีตในไฟล์นั้นและหัวตารางชั้นเดียว
- ตารางต้องมีรหัสและยอดเงิน/ข้อมูลรายการที่รู้จักอย่างน้อย 3 ชื่อ หากเป็นไฟล์แบบ 2 คอลัมน์หรือชื่อเฉพาะให้ตั้งแถวเองแล้วจับคู่คอลัมน์
- บังคับ HCODE, HSUB, HCODE_PAID เป็น string 5 หลัก ค่าว่าง/รหัสผิดไม่ถูกเปลี่ยนเป็น `00000` และไม่ใช้คอลัมน์รหัสผิดในการรวมยอด
- เงินรวมใช้จำนวนเต็มหน่วยสตางค์ รองรับ comma และจำนวนลบแบบวงเล็บ ยอดเงินว่างหรือผิดไม่ถูกแทนด้วยศูนย์
- ตัดแถวว่าง แถวรวม และหัวตารางที่พิมพ์ซ้ำกลางรายงาน รายการที่รหัส/ยอดเงินผิดยังอยู่ในรายละเอียดและมีตารางปัญหาให้ตรวจ
- ไฟล์ที่เนื้อหาเหมือนกันถูกอ่านครั้งเดียว มีตัวเลือกตัดแถวธุรกิจที่เหมือนกันข้ามไฟล์/ชีต โดยรักษาจำนวนรายการซ้ำในชีตเดิมและรายการที่ TRAN_ID เหมือนแต่ยอดต่างกัน หากแถวเหมือนกันเป็นคนละรายการจริงให้ปิดตัวเลือกนี้
- ค้นหารหัสตรงรหัสหน่วยบริการเป้าหมายเท่านั้น ชื่อค้นหาแบบ literal ไม่ใช้ regex ทะเบียน 19 หน่วยคงที่และดูได้ใน sidebar
- ข้อมูลนำเข้าเก็บเฉพาะ session ไม่ cache ข้ามผู้ใช้ Export ใช้ BytesIO ไม่เขียนไฟล์ผู้ป่วยบนเซิร์ฟเวอร์ ป้องกันข้อความนำเข้าไม่ให้กลายเป็นสูตร Excel
- HN/AN/PID ที่ถูก Excel บันทึกเป็นตัวเลขจนเลขศูนย์หาย ไม่สามารถกู้ศูนย์ได้หากไม่ทราบความยาวที่ถูกต้อง กฎเติมศูนย์ 5 หลักใช้เฉพาะรหัสหน่วยบริการ
- ไม่รองรับ HTML ที่ปลอมเป็น .xls, ไฟล์เข้ารหัส, macro และหลายตารางในชีตเดียว หากเป็น HTML จะมีข้อความแจ้งให้แปลงเป็น Excel จริง

### สรุปบริการที่ผู้ใช้ตรวจจากเคลมจริง
- ยึดคอลัมน์ `บริการ` และชื่อที่ผู้ใช้บันทึกแก้ไขก่อนการประมาณการจากราคา เช่น FIT test 30 บาทยังเป็น FIT test ตามไฟล์
- นิยามของหน่วยงาน: HC = ยาทั่วไป, HC-DRUG = สมุนไพร, PP = ส่งเสริมป้องกัน, FS = วางแผนครอบครัว โดยเก็บยอดตามคอลัมน์ต้นทางเสมอ
- รวมชื่อสมุนไพรไว้ในกลุ่มเดียว รายการที่มีสมุนไพรร่วมกับหมวดอื่นแสดงแยกเพื่อกระทบยอด สมุนไพรรวมทางการเงินใช้ HC-DRUG ทุกแถวเท่านั้น
- กรองกลุ่มบริการและยอดชดเชยต่อรายการ ดูจำนวนแถว ยอดบวก ยอดติดลบ ยอดศูนย์ และ Export สรุปบริการแยกราคาได้ จำนวนรายการไม่ใช่จำนวนผู้ป่วย
- นำเข้าชีตรายการต้นทางที่มี HSUB/HCODE ไม่ใช้ Pivot หรือชีตสำเนาที่ตัดรหัสหน่วยบริการออก แถวรวมที่ไม่มีรหัสหน่วยบริการไม่ถูกรวมในยอดบัญชีหน่วยนั้น
